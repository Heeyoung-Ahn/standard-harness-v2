## 1. 배경

하네스 기반 프로젝트를 운영하면서 다음 세 가지가 제품 품질과 장기 운영성에 핵심이라는 점을 확인했다.

1. 기획이 탄탄해야 LLM이 사용자의 의도에 맞게 구현한다.
2. 구현 후 리뷰가 엄격해야 제품 완성도가 높아진다.
3. 장기 기억과 프로젝트 맥락이 보존되어야 장기화되는 프로젝트에 대응할 수 있다.

이에 따라 Planning Pipeline, Design Planning System, Review Governance, Wiki Knowledge Architecture hardening 아이디어를 검토했다.

## 2. V2.1 추가 개선 범위

현재 V2.1 hardening에는 추가 보완이 필요한 부분이 일부 발견되었다.
따라서 V2.1 추가 개선 범위에는 다음 두 항목만 포함한다.

### 포함

1. XP-10B Review Governance Gate

   * 리뷰 절차를 문서가 아니라 release-blocking evidence gate로 승격한다.
   * Review profile, review bundle, finding, evidence integrity, final adjudication, release self-test를 추가한다.
   * fake review evidence, placeholder commit, missing test log, unresolved P0 finding, stale review를 차단한다.

2. XP-05B Wiki Knowledge Architecture Hardening

   * Wiki를 source of truth가 아니라 validated projection / navigation layer로 강화한다.
   * Wiki skeleton, provenance, source tier, freshness, owner, review status, related HR/XP/packet/evidence를 강제한다.
   * Skill-facing index는 navigation projection으로만 사용하며, permission, gate, source-of-truth authority를 만들 수 없게 한다.
   * stale context, missing provenance, repeated correction을 friction/improvement loop에 연결할 수 있도록 준비한다.

### V2.1에서 제외하고 V2.2로 이월

1. Planning Pipeline Hardening

   * Requirements interview
   * PRD writing
   * Feature tree
   * Workflow / user-flow modeling
   * Requirement candidate normalization

2. Design Planning System

   * Wireframe projection
   * UI module contract
   * Design mockup contract
   * Browser validation expectation

## 3. V2.1 추가 개선 원칙

1. Review/Wiki hardening은 새 제품 기능이 아니라 V2.1 release/closeout 품질 강화 작업이다.
2. 기존 V2.1의 source-of-truth 구조를 유지한다.
3. Markdown, Wiki page, generated summary, review note는 canonical authority가 아니다.
4. Canonical authority는 structured requirements, policies, schemas, catalogs, validators, tests, trusted evidence, validated state, human decision records에 있다.
5. 새 artifact는 validator/gate가 실제 소비하는 경우에만 추가한다.
6. 모든 추가 작업은 schema → policy → validator → gate → evidence → test → manual 순서로 구현한다.
7. release gate가 정상 케이스만 확인하는 것이 아니라, 깨진 fixture를 실제로 차단하는 negative self-test를 가져야 한다.
8. 현재 V2.1 hardening에서 발견된 문제를 먼저 보완한 후 XP-10B와 XP-05B를 진행한다.
