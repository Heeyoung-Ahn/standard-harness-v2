# V2.1 Hardening Completion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete V2.1 hardening end to end by closing release evidence, security, metrics, review governance, Wiki knowledge, executable release gate, and maintainability gaps from `docs/reference/idea/V2.1 Hardening Master Plan.md`.

**Architecture:** Execute one hardening XP per dedicated branch. Each XP must start from clean `main`, run baseline regression, add failing tests first, implement minimal code/policy/schema/docs, update HR coverage and traceability where applicable, pass focused and full verification, push a PR, wait for CI/review, merge to `main`, pull locally, and delete the XP branch before the next XP starts.

**Tech Stack:** Python stdlib, `unittest`, local CLI through `tools/harness_cli.py`, existing `standard_harness` modules, JSON-compatible `.yaml` policy artifacts unless XP-MaintA explicitly changes that decision.

---

## Authority And Scope

This plan is executable planning guidance. It does not override:

- `_harness/requirements/**`
- `_harness/policies/**`
- `_harness/schemas/**`
- deterministic validators
- trusted evidence
- gate results
- human decision records

The hardening reference root is `docs/reference/idea/V2.1 Hardening Master Plan.md`.

V2.2-deferred scope remains excluded:

- Requirements interview and PRD writing.
- Feature tree and flow modeling.
- Requirement candidate normalization.
- Wireframe projection.
- UI module and design mockup contracts.
- Portfolio/workstream/release-train operating layers.
- Planning Pipeline Hardening.
- Design Planning Hardening.

## Common XP Lifecycle

Use this lifecycle for every XP branch.

- [ ] **Step 1: Confirm local main is current**

```powershell
git switch main
git pull --ff-only origin main
git status --short --branch
```

Expected:

```text
## main...origin/main
```

- [ ] **Step 2: Run baseline regression**

```powershell
python -m unittest discover -s tests
```

Expected: all tests pass. If tests fail or hang, stop and report before editing.

- [ ] **Step 3: Create the XP branch**

```powershell
git switch -c <xp-branch>
```

Expected: branch is created from current `main`.

- [ ] **Step 4: Write focused failing tests**

Run the focused test command listed in the XP task. Confirm RED for the behavior that the XP is supposed to add. A test that passes before implementation does not prove the new behavior.

- [ ] **Step 5: Implement minimal changes**

Touch only the files listed in the XP. If implementation requires extra files, record why in the XP final report before committing.

- [ ] **Step 6: Update release metadata**

When applicable, update:

```text
_harness/requirements/hr-coverage-matrix.yaml
_harness/requirements/traceability-matrix.yaml
_harness/policies/validator-catalog.yaml
docs/release/v21-conformance-report.md
docs/release/release-packaging-hygiene-v21.md
```

- [ ] **Step 7: Run focused and release verification**

Run the XP focused tests, then:

```powershell
python tools\harness_cli.py --json validate --requirements-metadata
python tools\harness_cli.py --json validate --v21-conformance
python tools\harness_cli.py --json validate --release
python -m unittest discover -s tests
git status --short --branch
```

Expected: all validation commands pass, full regression passes, and only intended files are changed.

- [ ] **Step 8: Commit intended files only**

```powershell
git add <intended files only>
git diff --cached --name-only
git commit -m "<focused XP hardening message>"
```

Expected: staged files match the XP file list. Do not use broad `git add tests` or `git add src`.

- [ ] **Step 9: Push, PR, CI/review, merge**

```powershell
git push -u origin <xp-branch>
gh pr create --base main --head <xp-branch> --title "<XP title>" --body "<verification evidence and risk summary>"
gh pr checks --watch
gh pr merge --squash --delete-branch
git switch main
git pull --ff-only origin main
git branch -d <xp-branch>
git status --short --branch
```

Expected:

```text
PR CI/review passes.
PR is merged into origin/main.
Remote XP branch is deleted.
Local main is fast-forwarded to origin/main.
Local XP branch is deleted.
Working tree is clean.
```

If CI fails, review requests changes, merge conflicts appear, or `git pull --ff-only` cannot fast-forward, stop and repair in the same XP branch before merging.

---

## Stop Conditions

Stop before editing or continuing if:

- Baseline regression fails or hangs.
- `git status --short` contains unrelated dirty files.
- Repo-root generated state remains after cleanup.
- A v1 artifact, `.agents`, `.harness`, plugin, generated state, runtime state, or starter payload would need to be copied or promoted.
- External services, credentials, browser login, network validation, or cloud dependencies are required.
- Markdown, Wiki pages, PRD drafts, generated summaries, mockups, or review notes would become canonical authority.
- Existing V2.1 closed defaults would change without an explicit design decision.
- SECRET or SENSITIVE evidence might enter Wiki, handoff context, context packs, or LLM context.
