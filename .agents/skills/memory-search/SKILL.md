# Memory Search

Use this skill before planning or debugging when prior project learning may overlap the current request.

## Use When
- A problem resembles a past failure, review finding, operator issue, or recurring harness pattern.
- Planning, debugging, or remediation could benefit from prior preventive memory.
- The user asks whether this happened before.

## Do Not Use When
- The task is urgent and memory search would delay a required stop or safety action.
- Memory would be treated as higher authority than the active packet, requirements, or user instruction.
- The search would expose secrets or unrelated private project details.

## Workflow
1. Define the current symptom, route, or decision question.
2. Search the approved learning or preventive-memory surface using narrow terms.
3. Classify matches as applicable, adjacent, stale, or not relevant.
4. Apply only applicable lessons that do not conflict with current authority.
5. Record when no prior learning is found.

## Evidence To Produce
- Search terms or memory source.
- Relevant matches and applicability.
- Applied rule or no-prior-learning note.

## Authority Boundary
This skill searches memory. It must not override active requirements, approve work, or import stale/private history into the current task without source review.
